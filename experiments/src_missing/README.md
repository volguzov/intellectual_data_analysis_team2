# Помогает ли модели явный признак отсутствующего адреса?

В учебной модели доля частных IP для пустого `src` заполняется медианой обучения. Проверили, станет ли модель реже пропускать инциденты, если дать ей отдельный флаг «адрес пропущен». Для этой версии модели сохраняем исходный набор признаков. На карточках без адреса выигрыш по числу обнаруженных инцидентов менял знак между запусками.

## Как сравнивали

Взяли полную выгрузку `iavd_ml_dataset.parquet` и применили фильтры LightGBM v001. Оставили карточки с вердиктом «Решён» или «False Positive» и указанным правилом корреляции. Исключили ручной ввод. Разбиение июня, июля и августа 2025 года воспроизвели по конфигурации курса. Для обучения использовали 14 805 карточек, для выбора порога 3 172, для внутренней проверки 3 173. Преобразование общих полей сохранили таким же, как у v001. Для исходного запуска с числом 42 оценки переобученной модели совпали с опубликованной версией на каждой карточке следующего периода.

Флаг равен единице, когда в поле источника после разбора отсутствует значение. На обеих выборках он во всех случаях совпал с условием `len_src == 0`. Сравнили четыре набора признаков. Во всех вариантах оставили исходное поле адреса и счётчики. Меняли только наличие флага и доли частных IP. Каждую пару моделей обучили на одних и тех же карточках с одинаковыми параметрами. Для проверки устойчивости повторили обучение с числами 42, 43 и 44, сохранив разбиение.

## Сколько инцидентов увидела бы смена

С 1 сентября по 20 ноября 2025 года под условия оценки попали 19 924 карточки. Из них 2 127 оказались инцидентами и 17 797 легитимными событиями. Основное сравнение использует для всех моделей рабочий порог курса 1,9259%. Таблица показывает запуск с настройкой случайности курса.

| Признаки модели | Обнаружено из 2 127 | Пропущено | Ложные тревоги |
|---|---:|---:|---:|
| Исходная v001 | 1 789 | 338 | 2 819 |
| Исходные и флаг отсутствия адреса | 1 792 | 335 | 2 739 |
| Без доли частных IP | 1 773 | 354 | 2 604 |
| Флаг вместо доли частных IP | 1 784 | 343 | 2 860 |

На всём периоде добавление флага дало три дополнительных обнаружения и на 80 меньше ложных тревог. Модель обнаружила 19 прежних пропусков и пропустила 16 инцидентов, обнаруженных исходной моделью. При замене доли частных IP флагом баланс ухудшился по обоим показателям. Простое удаление доли сократило число ложных тревог на 215 ценой 16 дополнительных пропусков.

## Помог ли флаг именно при пустом адресе

| Адрес источника | Подтверждённых инцидентов | Обнаружено исходной моделью | Обнаружено с флагом | Ложные тревоги исходной модели | Ложные тревоги с флагом |
|---|---:|---:|---:|---:|---:|
| Отсутствует | 1 305 | 1 008 | 1 005 | 2 287 | 2 094 |
| Указан | 822 | 781 | 787 | 532 | 645 |

Среди карточек без адреса модель с флагом обнаружила 12 прежних пропусков и потеряла 15 прежних обнаружений. Итоговый выигрыш по всему потоку пришёлся на карточки с заполненным адресом.

При общем пороге изменение числа обнаруженных инцидентов за три запуска составило соответственно **+3, +13 и 0**, а изменение числа ложных тревог **−80, −43 и +61**. В самой группе с пустым адресом изменение числа обнаружений составило **−3, +8 и +1**. Это три запуска на одном временном периоде. Карточки этого периода уже входили в предшествующий анализ источника, поэтому проверка на новом периоде оставалась бы отдельным исследованием.

## Что меняется при выборе собственного порога

Отдельно выбрали для каждого варианта порог с максимальной F2 на июньской, июльской и августовской валидации. В исходном запуске для v001 получились те же 1,9259%, а для модели с флагом 3,7354%. На следующем периоде модель с флагом при своём пороге обнаружила 1 758 инцидентов и подала 2 093 ложные тревоги. Это на 31 обнаруженный инцидент и на 726 ложных тревог меньше исходной модели при её пороге. Качество ранжирования по средней точности (average precision) в этом запуске составило 0,66994 у исходной модели и 0,67006 у модели с флагом.

Явный флаг доступен на момент прогноза, но повторяет информацию, которую модель уже получает через длину списка. На проверенном периоде устойчивого сокращения пропусков на карточках без адреса не получилось. Оснований заменять модель для смены по этому результату недостаточно.

## Как воспроизвести

Откройте PowerShell в корне репозитория. Подготовьте окружение Python 3.11 и положите в папку `data` два входа для расчёта.

1. Распакуйте комплект практики так, чтобы папки `course_ml` и `models` находились в `data/IAVD_3.7_ML_team/`. [Комплект ML практики 3.7](https://disk.yandex.ru/d/waiZmiOzun8EZA/3.7_%D0%9F%D1%80_XAI/IAVD_3.7_ML_team.zip)
2. Сохраните полную выгрузку как `data/iavd_ml_dataset.parquet`. [Данные для обучения](https://disk.yandex.ru/d/waiZmiOzun8EZA/Datasets/%D0%97%D0%B0%D0%B4%D0%B0%D0%BD%D0%B8%D0%B5%202%3A%20%D0%98%D0%BD%D1%84%D0%B5%D1%80%D0%B5%D0%BD%D1%81%20%D0%BC%D0%BE%D0%B4%D0%B5%D0%BB%D0%B8/%D0%9F%D0%BE%D0%B4%20%D0%BE%D0%B1%D1%83%D1%87%D0%B5%D0%BD%D0%B8%D0%B5/iavd_ml_dataset.parquet)

```powershell
py -3.11 -m venv .venv
& '.\.venv\Scripts\python.exe' -m pip install -r requirements_shap.txt
& '.\.venv\Scripts\python.exe' experiments/src_missing/compare_models.py
```

При готовом окружении задания 3 достаточно последней команды. Параметры `--course` и `--data` позволяют указать другое расположение входных файлов. Скрипт сохраняет агрегированные показатели в `data/src_missing_metrics.csv`. Для сверки используйте таблицу из репозитория. [Результаты 12 обучений](metrics.csv)

Одна строка относится к сочетанию модели, запуска, выборки и способа выбора порога. По четырём вариантам, трём запускам, восьми выборкам и двум способам выбора порога получаются 192 строки. Для основной таблицы выше выберите `seed=42`, `group=post` и `policy=fixed`. Для карточек без адреса укажите `group=post_missing`. Числа обнаружений, пропусков и ложных тревог записаны в `tp`, `fn` и `fp`. Значение `validation_F2` обозначает отдельный порог по валидации. Поля `gained_tp` и `lost_tp` показывают переходы у одних и тех же инцидентов относительно исходной модели того же запуска.
